# 新版範例的邊界

C3 的 INTJ 範例完全虛構，用於測試協定、收件、顯示、Email gate 和 PNG；不是任何人的使用紀錄，也不是舊分型的轉換或真人結果。

三個獨立目標分別設為 10/01 製作藏書搜尋原型、10/04 比較雨水收集方案、10/09 規劃讀書會流程。每個目標都假設有足夠資訊、兩端方法皆可選，並觀察到：
- 先整理成一份可見的完整交付，再回報主人（I）。
- 從問題模式與替代可能性展開（N）。
- 在兩個合理方向的衝突中採一致比較準則決定取捨（T）。
- 在仍可探索的情況先約定路線與里程碑（J）。

第一、三個目標有對應主人要求；第二個未指定方向。任務名稱與敘事只在這份虛構情境說明，沒有放入提交 JSON。JSON 的 source/context/date 與 ownerRequest/behavior 是模型輸入，不證明真實世界已觀察到該行為。

partial-workstyle.json 刪去所有 T/F 觀察，結果 IN?J、type:null。insufficient-evidence.json 為零可用任務、零觀察、未知用量。collector-review-input.json 使用相同未知範例且 aggregateUploadApproved:false。public 空白模板同樣不授予任何同意，日期尚未填寫，故不能直接提交。

測試另建立同任務重複、兩個 task、2:1、3:2、混合 task、情境受限、owner mismatch、未知來源與舊協定案例。沒有預先指定任何真人應屬的型別。
